# VDF Assignment-2 — Verilog Modelling, Simulation, Code Coverage and Logic Synthesis

Implementation of a five-state Mealy finite state machine in Verilog, verified by
simulation and code coverage, and synthesised with two different state encodings
so the results can be compared.

Course: VLSI Design Flow
Tools: Icarus Verilog, GTKWave, Covered, Yosys (all open source)

---

## 1. The state machine

Five states (S1–S5), a 2-bit input and a 2-bit output. Outputs are labelled on the
transition arcs, so the machine is **Mealy** — the output depends on both the
current state and the current input, not on the state alone.

Transition table (`next state / output`):

| State | in = 00 | in = 01 | in = 10 | in = 11 |
|-------|---------|---------|---------|---------|
| S1    | S1 / 01 | S1 / 00 | S2 / 01 | S3 / 00 |
| S2    | S1 / 11 | S3 / 11 | S2 / 10 | S4 / 10 |
| S3    | S1 / 00 | S5 / 01 | S3 / 10 | S4 / 00 |
| S4    | S3 / 11 | S5 / 01 | S5 / 01 | S4 / 11 |
| S5    | S5 / 00 | S1 / 00 | S3 / 00 | S5 / 11 |

Every state has exactly four outgoing arcs, one per input value — 20 arcs in total.
Reset is synchronous and active high: with `rst` asserted, the next rising clock
edge loads S1.

### State encodings

**Gray** (`fsm_gray.v`) — 3 bits, consecutive codes differing in a single bit:

```
S1 = 000    S2 = 001    S3 = 011    S4 = 010    S5 = 110
```

Only one flip-flop toggles when the machine steps between adjacent states, which
lowers switching activity and avoids decode glitches caused by several bits
changing at slightly different times. Codes `100`, `101` and `111` are unused and
a `default` branch maps them back to S1, so the machine cannot lock up.

**One-hot** (`fsm_onehot.v`) — 5 bits, one flip-flop per state:

```
S1 = 00001  S2 = 00010  S3 = 00100  S4 = 01000  S5 = 10000
```

## 2. Files

### RTL

| File | Description |
|------|-------------|
| `fsm_gray.v` | Gray-encoded FSM. Two always blocks: a synchronous state register and a combinational next-state/output block. |
| `fsm_onehot.v` | Same machine, one-hot encoded. Functionally identical. |

Both carry `(* fsm_encoding = "none" *)` on the state register — see section 5 for
why this matters.

| File | Description |
|------|-------------|
| `tb_fsm.v` | Self-checking testbench with an encoding-independent reference model. Drives both designs. |

## 3. How to run

### Install

```bash
sudo apt install iverilog gtkwave yosys graphviz
```

Covered is not packaged. Build from source:

```bash
sudo apt install -y gperf tcl-dev tk-dev flex bison
git clone https://github.com/chiphackers/covered.git
cd covered
sed -i 's/interp->result/Tcl_GetStringResult(interp)/g' src/report.c
./configure && make && sudo make install
```

The `sed` line is required on modern systems: Tcl 8.6 removed the public
`interp->result` field that Covered's 2009-era source reads directly.

### Simulate

```bash
# gray
iverilog -Wall -o test_gray fsm_gray.v tb_fsm.v
vvp test_gray

# one-hot — same testbench, selected by -DONEHOT
iverilog -Wall -DONEHOT -o test_onehot fsm_onehot.v tb_fsm.v
vvp test_onehot
```

Both print 25 checked vectors ending in `TEST PASSED`. The logs are identical,
which is what confirms the two encodings are functionally equivalent.

### View waveforms

```bash
gtkwave fsm.vcd
```

Add `clk`, `rst`, `in`, `out` from `tb_fsm`, then `cur_state` and `next_state`
from the `dut` scope. Set the state signals to binary format.

### Coverage

```bash
iverilog -Wall -o test_cov fsm_gray.v tb_cov.v
vvp test_cov
covered score -t tb_cov -v tb_cov.v -v fsm_gray.v -vcd fsm_cov.vcd -o fsm.cdd
covered report -d v fsm.cdd
```

### Synthesise

```bash
yosys -s syn_gray_lib.ys
yosys -s syn_onehot_lib.ys
```

## 4. Results

### Verification

The testbench walks a directed sequence of 24 vectors covering **all 20 arcs** of
the state diagram, then applies a reset from a non-initial state. A reference
model written from the state diagram — using plain state numbers, so it is
independent of the encoding — predicts the expected output for every vector and
any mismatch is reported.

Coverage on `fsm_gray.v`:

| Metric | Result |
|--------|--------|
| Line | 49 / 49 (100%) |
| Toggle | 12 / 12 both directions (100%) |
| Combinational logic | 18 / 18 (100%) |

The unreachable `default` branch does not appear as a miss: the elaborator finds
the case statement full and treats the branch as unreachable, so it never enters
the denominator.

Note that coverage measures what the stimulus *reached*, not whether the results
were correct. A testbench running the same walk and checking nothing would score
identically. Correctness comes from the reference-model comparison.

### Synthesis (mapped to `simple.lib`)

| Metric | Gray (3-bit) | One-hot (5-bit) | Change |
|--------|--------------|-----------------|--------|
| Chip area | 147.0 | 201.0 | +37% |
| Flip-flops | 3 | 5 | +2 |
| Flip-flop area | 36.0 | 60.0 | +67% |
| Combinational area | 111.0 | 141.0 | +27% |
| Total cells | 59 | 74 | +25% |

**Gray is smaller on every metric**, which runs against the usual expectation that
one-hot buys simpler combinational logic. The reason is scale. One-hot is
advocated because testing "am I in state Sk" costs a single wire, while a dense
encoding needs a decode gate — but that saving is small when the register is only
three bits wide. Against it sits a cost independent of the decode: five
next-state bits must be computed rather than three, and each is the OR of every
arc arriving at that state. With 20 arcs over 5 destinations that arrival logic
is substantial, and it shows up as NOR2X1 rising from 24 to 33.

The advantage of one-hot grows with state count, so a machine with tens of states
would be expected to reverse this result. One-hot also remains the natural choice
on FPGAs, where each logic cell already contains a flip-flop and LUT depth sets
the speed.

This is an **area** comparison. The usual argument for one-hot concerns critical
path depth and clock frequency, which would need static timing analysis against
the library timing tables to establish.

## 5. A note on `fsm_encoding`

Yosys detects a state register by default, extracts it into an abstract FSM object
and re-encodes it with its own heuristic. On the first synthesis run the log
reported:

```
Found FSM state register fsm_gray.cur_state
...
mapping auto encoding to `one-hot' for this FSM
```

The gray encoding was silently discarded and the resulting netlist contained a
`$fsm` cell and **no flip-flops at all**. Any comparison between the two designs
would have been meaningless, since both would map to the same internal encoding.

Adding `(* fsm_encoding = "none" *)` to the state register fixes this. With it,
`FSM_DETECT` reports no FSM found and the chosen encoding survives into the
netlist.

Worth remembering generally: a synthesis result reflects the RTL *and* the tool
settings, not the RTL alone.

## 6. Coding practices applied

- Both latch-avoidance rules: a `default` case covering every path, and default
  values assigned at the top of the combinational block. The synthesised netlist
  contains no latches, confirming this worked.
- `@(*)` sensitivity list, so no input can be accidentally omitted.
- Non-blocking assignment (`<=`) in the sequential block, blocking (`=`) in the
  combinational block.
- Unused state codes recovered to S1 rather than left undefined.
